# Monaco Editor for the JSON input

We use Monaco (`@monaco-editor/react` + `monaco-editor`) instead of a plain textarea for the Dataset input, because real-world JSON is long and deeply nested: folding, bracket matching, JSON validation and large-document scrolling are what make the input usable, and a soft-wrapped textarea degrades quickly. Monaco is loaded from the local bundle via `loader.config({ monaco })` rather than its default CDN, so the tool keeps working offline; we import only `monaco-editor/editor/editor.api` plus the JSON language contribution instead of the `monaco-editor` root barrel, which registers every language and drags in ~7 MB of TypeScript/CSS/HTML workers — the root barrel is not worth it for a JSON-only tool. Workers are wired with Vite `?worker` imports and `self.MonacoEnvironment`. Consequence for tests: the editor is a heavyweight DOM dependency that needs a worker, so `src/JsonEditor.tsx` is stubbed with a textarea in the App tests; the editor itself is verified in the browser, not in jsdom.
